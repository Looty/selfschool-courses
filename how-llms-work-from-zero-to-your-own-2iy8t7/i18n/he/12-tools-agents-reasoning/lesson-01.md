לאחר שיעור זה תוכלו להסביר כיצד מודל שמסוגל לייצר טקסט בלבד יכול להשתמש במחשבון או במנוע חיפוש, ובאילו נקודות טמונים הסיכונים.

## מודל יכול רק לכתוב טקסט

מודל שפה מייצר טוקנים (tokens). הוא אינו יכול לבדוק מה מזג האוויר היום, להריץ קוד או לשלוח שאילתה למסד נתונים. אבל טקסט יכול לתאר פעולה, ותוכנית נפרדת יכולה לבצע אותה. הסקירה בוויקיפדיה מתארת שימוש בכלים באופן הזה: תוכנית נפרדת עוקבת אחר הפלט של המודל ומחפשת בו תחביר של קריאה לכלי, מריצה את הכלי ומזינה את התוצאה בחזרה למודל. [21]

## הלולאה

1. ההנחיה (prompt) מתארת את הכלים הזמינים ואת הפורמט לקריאה אליהם (לדוגמה `calculator[1234 * 5678]`).
2. המודל כותב תשובה. אם הוא רוצה להשתמש בכלי, הוא כותב קריאה בפורמט הזה ועוצר.
3. התוכנית העוטפת מזהה את הקריאה, מריצה את הכלי ומוסיפה את התוצאה לשיחה.
4. המודל מורץ שוב, והפעם התוצאה נמצאת בהקשר (context) שלו. הוא ממשיך, ולעיתים קורא לכלים נוספים, עד שהוא כותב תשובה סופית.

המודל לעולם אינו מריץ דבר בעצמו. כל מה שנוגע בעולם החיצון מבוצע על ידי התוכנית שלכם, ולכן זה המקום להציב בו בדיקות.

## למה זה עוזר

מודלים טובים בשפה, אך אינם אמינים בחישוב אריתמטי מדויק, בעובדות עדכניות ובחישובים ארוכים (שיעור 3). כלים ממלאים את הפערים האלה. בניסויים במאמר ReAct נעשה שימוש בממשק API פשוט של ויקיפדיה ככלי חיצוני, ונמצא שהוא הפחית את ההזיות (hallucination) ואת התפשטות השגיאות שפגעו בהנמקת שרשרת מחשבה (chain-of-thought) טהורה במשימות מענה על שאלות. [13]

## ללמד את המודל מתי לקרוא: Toolformer

בתבנית ReAct פורמט הכלי מתואר בהנחיה. המאמר Toolformer (Schick ואחרים, פברואר 2023) שאל אם מודלים יכולים *ללמוד* להשתמש בכלים. נקודת המוצא של המאמר היא התצפית שמודלי שפה מצליחים במשימות רבות, אך מועדים לטעות במשימות פשוטות, כמו חשבון או שליפת עובדות, שבהן מערכות מיוחדות קטנות בהרבה מצטיינות. Toolformer מאומן באופן מונחה-עצמי (self-supervised), עם מספר קטן בלבד של דוגמאות לכל API, להחליט לאילו ממשקי API לקרוא, מתי לקרוא להם, אילו ארגומנטים להעביר וכיצד לשלב את התוצאות בחיזוי הטוקנים הבא. [57] הכלים שלו כללו מחשבון, מערכת מענה על שאלות, שני מנועי חיפוש, מערכת תרגום ולוח שנה, והוא שיפר את הביצועים ב-zero-shot במגוון משימות, פעמים רבות עד כדי התאמה למודלים גדולים בהרבה, בלי לאבד את יכולת מידול השפה הבסיסית שלו. [57]

## סיכונים שיש לתכנן סביבם

- **המודל מחליט למה לקרוא.** התייחסו לפלט שלו כאל קלט לא מהימן. אמתו את הארגומנטים (במעבדה, המחשבון רואה רק ספרות ואופרטורים).
- **הגבילו את הלולאה.** מודל יכול לקרוא לכלים ללא סוף; קבעו מספר מרבי של סבבים.
- **הרשאות מינימליות (least privilege).** תנו לכלי רק את הגישה שהוא זקוק לה. כלי שיכול לשלוח דואר אלקטרוני או למחוק קבצים מהווה סיכון אם אפשר להטעות את המודל באמצעות טקסט שהוא קורא.
- **גם טקסט בתוצאות של כלים הוא טקסט של הנחיה.** דף אינטרנט שהמודל קורא יכול להכיל הוראות שמופנות אליו. (קורס ה-MLOps באפליקציה זו דן בהזרקת הנחיות, prompt injection.)

:::key-takeaways
- שימוש בכלים = המודל כותב קריאה מובנית, התוכנית שלכם מריצה אותה ומזינה את התוצאה בחזרה. [21]
- הוא מכסה חולשות של מודלי שפה גדולים (LLMs): חשבון מדויק, עובדות עדכניות, חישובים ארוכים. [13]
- התייחסו לקריאות של המודל כאל לא מהימנות: אמתו, הגבילו את מספר הסבבים ואת ההרשאות.
:::

:::glossary
- **שימוש בכלים / קריאה לפונקציות (Tool use / function calling)**: המודל מבקש, בפורמט קבוע, שתוכנית תורץ, ומקבל את התוצאה.
- **כלי (Tool)**: תוכנית שהמודל יכול לבקש להריץ, כמו מחשבון או חיפוש.
- **תחביר קריאה לכלי (Tool-calling syntax)**: פורמט הטקסט המדויק שבו המודל משתמש כדי לבקש כלי.
- **תצפית (Observation)**: תוצאת הקריאה לכלי, המוזנת בחזרה לשיחה.
- **הרשאות מינימליות (Least privilege)**: מתן גישה לרכיב רק במידה שהוא זקוק לה.
- **הזרקת הנחיות (Prompt injection)**: הוראות החבויות בטקסט שהמודל קורא, במטרה לחטוף את התנהגותו.
- **קלט לא מהימן (Untrusted input)**: נתונים שיש לבדוק כי אין לכם שליטה במקורם.
:::
